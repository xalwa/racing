# Проверка версии 3 Автогонки

Дата проверки: 8 ноября 2026 года. Основание: вариант 20 в i-tasks.pdf,
страницы 40–42, и i-tasks-req-03.pdf, страницы 5–9.

## Соответствие требованиям

| Требование | Реализация |
|---|---|
| C и Linux, активные участники в отдельных процессах | Судья и N машин; по умолчанию 7 процессов, максимум 33 |
| Общий родитель, POSIX-память и неименованные семафоры | race; fork, shm_open, mmap MAP_SHARED, sem_init с pshared=1 |
| Общий родитель, POSIX-память и именованные семафоры | race-named; fork, shm_open, sem_open |
| Независимые программы, память и именованные семафоры | race-judge и race-car |
| Независимые программы, очереди и именованные семафоры | race-mq-judge и race-mq-car; данные передаются через mq_send/mq_receive |
| Наглядный вывод и результаты | Поклеточные кадры, текстовый режим, классификация машин и команд |
| Сигналы и освобождение ресурсов | SIGINT/SIGTERM, завершение текущего раунда, ожидание участников, откат частичного запуска |
| Отчёт | REPORT.md, AKOS_report.pdf, output/AKOS_report.docx |

Все четыре реализации сохраняются одновременно. Соответствие техническим
уровням требований не определяет итоговую оценку преподавателя.

## Правила и инварианты

| Инвариант | Обеспечение и проверка |
|---|---|
| Одна машина в клетке | Маршрут исключает занятые клетки; занятость независимо восстанавливается по журналу |
| Нет движения назад и диагоналей | Три допустимых направления; координаты пересчитываются проверкой |
| Стоимость в пределах бюджета | Стоимость шагов 1, 1, 3; независимо проверяются сумма и бюджет следующего хода |
| Очередь обновляется после раунда | Судья фиксирует очередь на раунд; проверка сверяет продвижение и дорожки |
| Выбывшие не ходят | Разрешения получают только ACTIVE; проверяются события после схода и финиша |

Исходная клетка входит в множество посещённых. Повтор клетки запрещён
в течение всего хода. Нулевой ход снимает машину после конца раунда;
финишировавшая машина также остаётся препятствием до конца раунда.
Стоимость бокового перехода отделена от продвижения вперёд.

## Результаты проверок

Среда: Linux 7.2.15 x86_64, GCC 16.2.1, Python 3.14.10.
Команда полной проверки: `make -B test`. Завершилась с кодом 0.
Сборка C11 с -Wall -Wextra -Wpedantic -Werror -O2, -pthread и -lrt
создаёт шесть исполняемых файлов без диагностик.

| Проверка | Результат |
|---|---|
| Модель C | 3248 малых маршрутов, инварианты раунда и 200 гонок |
| CLI | 28 восстановленных журналов, две максимальные конфигурации, неверные параметры, повторяемость, ошибки вывода и сигналы |
| Первый вариант | 70 отказов запуска, 34 отказа destroy, искусственный EINTR, повторная очистка |
| Реальные процессы | 33 отдельных однопоточных процесса; выход детей, SIGINT/SIGTERM судье и группе, SIGKILL/SIGSTOP машины |
| Поклеточная анимация | 4201 кадр и 3370 переходов в четырёх гонках; координаты, занятость, бюджет, очередь, маршруты и цвета |
| Режимы вывода | Приоритет --no-animation при обоих порядках параметров; --quiet, перенаправление и TERM=dumb; восстановление терминала |
| Сравнение реализаций | 10 конфигураций greedy/random с разными seed; на восьми совпадают полные журналы, на двух максимальных совпадают краткие итоги |
| Именованный вариант с fork | 138 отказов: 4 операции с памятью, 34 sem_open, 32 fork, 34 sem_close и 34 sem_unlink |
| Независимая общая память | 34 отказа открытия семафоров судьи; после отката нет оставшихся имён |
| Очереди | 7 отказов открытия очередей/семафоров судьи и машины; запуск при принудительном отказе shm_open |
| Независимые подключения | Машина раньше судьи, обратный порядок ID, повторный/неверный ID, второй судья, неполный состав |
| Сессии | Параллельные гонки с разными параметрами; независимые машины не являются детьми судьи |
| Независимые кадры | Для обеих реализаций сверены кадры одной и шести машин; сигнал машине отменяет пятисекундную паузу судьи |
| Потеря участника | SIGKILL/SIGSTOP машины после регистрации всех; ошибка вместо бесконечного ожидания |
| Потеря судьи | Fork-дети завершаются; независимые машины удаляют имена оставшейся сессии |
| Журнал | При --quiet сохраняется полный текст; /dev/full обнаруживается, участники завершаются |
| Статический анализ | Все шесть модулей проверены GCC -fanalyzer без диагностик |

Именованный вариант с fork также отдельно проходит CLI- и покадровые
проверки с теми же результатами. Проверки независимых реализаций запускаются
отдельно: tests/test_variants.py и tests/test_variants.py --queues.

LD_PRELOAD подключает tests/faults.c только в тестах. Библиотека подменяет
выбранный вызов, остальные передаёт настоящим функциям. Искусственный EINTR
не является доставкой сигнала; реальные SIGINT/SIGTERM проверяются отдельно.
Наличие процессов проверяется через /proc и ожидание, имена памяти и
семафоров — в /dev/shm. Отсутствие очередей проверяется через mq_open
с ожидаемым ENOENT, независимо от монтирования /dev/mqueue.
Журналы и кадры проверяются независимо от race.c.

Совпадение журналов проверяет сохранение поведения при смене IPC. Правильность
правил дополнительно проверяют тесты модели и восстановление гонки по журналу.
Тесты охватывают перечисленные сценарии и не доказывают отсутствие всех ошибок.
Санитайзеры в итоговую проверку не входят.

## Границы модели и среды

Дорожки имеют одинаковую длину, боковой переход сохраняет сектор.
Круговые премии и дополнительное снятие отставших отключены. Стратегии
локальные; random использует отдельный seed + id для каждой машины.
В одном окружении результат одинаков во всех четырёх реализациях, но
последовательность random отличается от версии 2 с общим генератором.

Независимые реализации требуют pidfd. Очереди требуют доступных лимитов
POSIX MQ и достаточно свободной квоты пользователя. Сообщения ограничены
8192 байт, общая очередь содержит до четырёх сообщений, очередь машины — одно.
Замена процесса машины после начала гонки не предусмотрена.

SIGKILL не обрабатывается. При гибели одного судьи выжившие участники
очищают ресурсы. Одновременный SIGKILL всех независимых участников может
оставить имена сессии: процесса для очистки уже нет.

## Дополнительные материалы

В AI_PROMPTS.md приведены область использования ИИ и критическая оценка
реальных исправлений. Полный архив запросов не включён; дополнительное
требование о предоставлении всех промптов не заявляется как выполненное.
Вывод в терминал и журнал использует stdio; отдельная реализация всего
пользовательского вывода через низкоуровневые файловые дескрипторы не заявляется.

Комплект проверен после распаковки в отдельный временный каталог: собраны
все шесть программ, результаты четырёх реализаций совпали. Контрольные
суммы включённых файлов проверяются по SHA256SUMS внутри архива.
