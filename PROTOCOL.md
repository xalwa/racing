# TCP-протокол гонки

Машины и наблюдатели открывают отдельные TCP-соединения с судьёй.
Судья начинает гонку после регистрации всех машин, выдаёт ходы по одному
и хранит актуальное состояние трассы. Наблюдатели могут подключаться
до старта и во время гонки.

## Формат кадра

| Байты | Поле |
|---|---|
| 0–1 | ASCII `RC` |
| 2 | Версия протокола, сейчас 1 |
| 3 | Тип сообщения |
| 4–7 | Длина тела без заголовка, до 2048 байт |
| С 8 | Тело сообщения |

Числа в теле занимают четыре байта и записываются старшим байтом вперёд,
если не указано иначе. Продвижение — знаковое число в дополнительном коде.
Дорожки и клетки нумеруются с нуля. Клетка 0 — линия старта и финиша.
Получатель собирает заголовок и тело независимо от границ чтения сокета.

## Сообщения

| Тип | Направление | Тело в порядке передачи |
|---|---|---|
| 1 `HELLO` | Машина → судья | ID от 1 до числа машин |
| 2 `WELCOME` | Судья → машина | ID, базовый seed, стратегия (0 — greedy, 1 — random). При возврате машины также число уже использованных вызовов генератора |
| 3 `TURN` | Судья → машина | Номер хода, раунд, бюджет, дорожка, клетка, продвижение, число дорожек, длина, число кругов. Затем занятость трассы по дорожкам, один байт на клетку (0 — пусто, иначе ID) |
| 4 `MOVE` | Машина → судья | Номер хода, число переходов, по одному байту на переход (0 — вперёд, 1 — внутрь, 2 — наружу) |
| 5 `RESULT` | Судья → машина | Причина (1 — все финишировали или сошли, 2 — лимит раундов), число раундов, место машины, место команды, состояние, продвижение |
| 6 `ERROR` | Судья → клиент | Код ошибки (1 — формат сообщения, 2 — неверный ID, 3 — ID занят, 4 — гонка началась, 5 — неверный ход, 6 — недопустимый маршрут, 7 — достигнут предел наблюдателей) |
| 7 `WATCH` | Наблюдатель → судья | Пустое тело |
| 8 `VIEW` | Судья → наблюдатель | Снимок гонки |
| 9 `STANDINGS` | Судья → наблюдатель | Итоговый снимок гонки, текст события содержит причину завершения |
| 10 `STOP` | Судья → клиент | Причина (3 — судья остановлен сигналом, 4 — гонка прекращена из-за ошибки) |

Номер хода глобальный и начинается с 1. Судья проверяет номер, право
машины на ход и весь маршрут, затем применяет переходы. Стоимость судья
считает самостоятельно. Пустой маршрут принимается только при отсутствии
допустимого перехода из исходной клетки.

При переподключении с тем же ID судья выдаёт ожидающий ход с прежним
номером. Повтор последнего принятого `MOVE` этой машины не меняет трассу.
Клиент со стратегией random восстанавливает генератор через `seed + id`
и пропускает число значений из `WELCOME`. Счётчик пополняется после
применения маршрута, по одному вызову генератора на переход.

## Снимок гонки

`VIEW` и `STANDINGS` имеют один формат. Сначала идут 17 чисел в таком
порядке: раунд, предел раундов, команды, машины в команде, дорожки,
длина дорожки, круги, число финишировавших, ID выделенной машины (0 —
нет), шаг, число шагов, использованный бюджет, предел бюджета, число
переходов маршрута, число машин в очереди, длина текста в байтах,
интервал кадров в миллисекундах.

За заголовком идут машины в серверном порядке массива. У каждой шесть
чисел: ID, дорожка, клетка, состояние (0 — гонка, 1 — финиш, 2 — сход,
3 — не завершила), место финиша, продвижение. Затем следуют байты
занятости трассы, индексы очереди (с нуля), байты направлений маршрута
и текст события в UTF-8 без завершающего нуля.

При подключении зритель получает последний опубликованный снимок.
Затем сервер публикует кадры по порядку и рассылает их через неблокирующие
сокеты. Для каждого наблюдателя хранится номер следующего кадра. Если
зритель выбился за границу общей истории из 128 кадров, его соединение
закрывается. Гонка и остальные зрители продолжают работу.

## Остановка

При штатном завершении судья отправляет личные `RESULT` машинам и
`STANDINGS` наблюдателям. При SIGINT, SIGTERM или ошибке судья шлёт
`STOP`. Исходящие кадры обрабатываются не более двух секунд, затем
судья закрывает оставшиеся сокеты.
