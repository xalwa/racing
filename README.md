# АКОС: версия 2.0, ИДЗ № 2, вариант 20 «Автогонки»

Многопоточная консольная программа на C для Linux с использованием pthread.
Версия 2.0 разрабатывается в корне репозитория в ветке `v2.0`; предыдущая
последовательная версия сохранена в `main`. У каждой машины свой поток,
главный поток выполняет роль судьи. Реализованы жеребьёвка,
движение и смена дорожек, две стратегии, раунды, круги, блокирование,
нулевой ход и сход, финиш, результаты машин и команд.

Порядок дальнейшей работы описан в [PLAN.md](PLAN.md), роли потоков и
структура модулей — в [ARCHITECTURE.md](ARCHITECTURE.md). Сверка требований
и результаты находятся в [AUDIT.md](AUDIT.md), отчёт по ИДЗ №2 —
в REPORT.md и версиях Word/PDF, перечисленных ниже.

## Сборка и запуск

Из папки проекта:

```bash
make
./race
```

Без Make:

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -Werror -O2 -pthread main.c race.c display.c threads.c -o race
./race
```

По умолчанию гонка воспроизводима: 3 команды по 2 машины, 4 дорожки
по 24 клетки, 2 круга, максимум 100 раундов, seed 1, стратегия greedy.

## Анимация по клеткам

При обычном запуске в терминале анимация включается автоматически.
Между каждым переходом машины на соседнюю клетку выдерживается пауза
120 мс. Клетки обведены границами, машины обозначены номерами и окрашены
по командам; текущая машина дополнительно выделяется. На экране видны
номер шага, расход хода, дорожка, клетка, порядок участников,
выбранный маршрут и событие. В маршруте В означает вперёд,
И — внутрь, Н — наружу. Блокирование, нулевой ход и сход имеют отдельные кадры.
Для полного кадра с очередью и всеми дорожками используйте окно не меньше
80 столбцов и 24 строк. На более широкой трассе отображается участок около
текущей машины.

Чтобы подробнее рассмотреть каждый переход:

```bash
./race --delay 300
```

Экран перерисовывается на месте. Для длинной трассы показывается участок
около текущей машины, помещающийся по ширине терминала. После гонки или
Ctrl+C обычный экран и курсор восстанавливаются, затем выводятся результаты.

`--no-animation` или `--delay 0` включают обычный текстовый вывод.
`--no-animation` имеет приоритет над `--delay` при любом порядке аргументов;
в этом режиме кадры и паузы отключены.
При `--quiet`, перенаправлении stdout или `TERM=dumb` анимация и задержки
отключаются автоматически. Полный журнал `--log` остаётся текстовым
и содержит все события, независимо от анимации.

## Параметры

```bash
./race --help
./race --teams 4 --laps 3 --rounds 200 --seed 42
./race --strategy random --seed 7
./race --quiet --log race.log
```

| Параметр | Значение по умолчанию | Допустимые значения |
|---|---:|---|
| --teams | 3 | 1–8 команд |
| --cars | 2 | 1–4 машины в команде |
| --lanes | 4 | 1–6 дорожек |
| --length | 24 | 3–120 клеток на каждой дорожке |
| --laps | 2 | 1–100 кругов |
| --rounds | 100 | 1–10000 раундов |
| --seed | 1 | 0–4294967295 в текущем Linux-окружении |
| --strategy | greedy | greedy или random |
| --log | без файла | Путь к полному журналу |
| --quiet | выключен | Краткий вывод на экран; журнал остаётся полным |
| --delay | 120 | 0–5000 мс между переходами; 0 отключает анимацию |
| --no-animation | анимация в терминале | Обычный текстовый вывод |

На дорожке должно быть больше клеток, чем машин на старте. Например,
для 8 команд по 4 машины нужно добавить --length 33 или больше.

Файл --log открывается для перезаписи. В нём сохраняются параметры,
все события, состояния трассы и итоговые таблицы. Ошибки числовых
параметров, открытия и записи журнала обнаруживаются программой.

## Как устроена модель

- Кольцо разделено на продольные секторы; все дорожки содержат одинаковое
  число клеток. Это выбранная трасса, а не точная копия поворотов рисунка.
  При движении вперёд после последней клетки идёт первая.
- Дорожка 1 — внутренняя. Машины стоят на внешней дорожке перед общей
  стартовой линией, которая также является финишной.
- Жеребьёвка определяет порядок команд. Сначала стоят первые машины всех
  команд, затем следующие в том же порядке.
- Продвижение перед стартом отрицательное: -1 у лидера, -2 у следующего.
  Первое пересечение линии даёт 0; первый полный круг завершается при
  продвижении, равном длине дорожки.
- Боковой переход не увеличивает продвижение. Вперёд и внутрь стоят 1,
  наружу — 3 единицы движения.
- Предел лидера — 4; второй машины — фактическая стоимость хода лидера + 2;
  остальных — фактическая стоимость предыдущего хода + 1.
- Порядок участников фиксирован на весь раунд. При его формировании выше
  большее продвижение, затем внутренняя дорожка, затем меньший номер машины.
- greedy выбирает вперёд, иначе внутрь, иначе наружу. random выбирает
  случайный допустимый шаг. Обе стратегии исключают занятые и посещённые
  в текущем ходе клетки; начальная клетка тоже считается посещённой.
- Нулевой ход означает, что невозможно сделать ни одного допустимого
  перехода. Он приводит к сходу в конце раунда.
- Финиш обрывает маршрут точно на линии. Финишировавшие и машины
  с нулевым ходом остаются препятствиями до конца раунда.
- Круговые премии и дополнительные правила снятия отставших отключены,
  как разрешено условием.
- Финишировавшие ранжируются по очереди финиша; все остальные — по
  достигнутому продвижению, внутренней дорожке и номеру машины.
  Команды сравниваются по месту своей лучшей машины.
- Гонка заканчивается после финиша/схода всех машин либо по лимиту раундов.
  При лимите оставшиеся получают состояние «не завершила».

Числа дорожек и клеток в выводе начинаются с единицы. Точка означает
свободную клетку, число — номер автомобиля. Для снятых машин таблица
показывает последнее положение, но на схеме трассы их уже нет.

Одинаковые параметры и seed дают одинаковый журнал в одной сборке
и окружении. Реализация rand() зависит от libc, поэтому результаты
между разными платформами могут отличаться.

## Прерывание

Ctrl+C (SIGINT) и SIGTERM завершают текущий раунд, сохраняют результаты
и закрывают журнал. Оставшиеся машины отмечаются как «не завершила».
Задержки отображения отменяются. Если сигнал получен при создании потоков,
гонка не начинает первый раунд; созданные потоки завершаются через общий
порядок остановки.

Судья пробуждает ожидающие потоки, присоединяет каждый через pthread_join,
затем уничтожает семафоры и мьютекс. При неполном запуске освобождаются
только успешно созданные объекты. Ошибка уничтожения одного объекта не
отменяет попытку освобождения остальных; она выводится в stderr и приводит
к коду 1. Код 1 также имеет приоритет над кодом сигнала при ошибке записи.

Коды завершения: 0 — обычное завершение или лимит, 1 — ошибка,
130 — SIGINT, 143 — SIGTERM.

## Проверка

Для запуска тестов нужны Python 3 и Git. Сравнение с первой версией читает
её исходник из коммита `3480fc4cf98ce7653480a155baa3fd36151f2a16` и собирает
его во временной папке, не меняя текущую ветку и рабочие файлы:

```bash
make test
```

Отдельно проверить завершение и отказы создания и освобождения ресурсов:

```bash
make test-shutdown
```

Отдельно проверить кадры анимации и согласованность журнала:

```bash
make test-display
```

На C проверяются отдельные правила, 3248 маршрутов на малых трассах,
пересчёт порядка после раунда, неподвижность выбывших и 200 гонок
со сверкой каждого маршрута и состояния. На Python независимо восстанавливаются 28 журналов
гонки; также проверяются параметры, повторяемость, журнал, ошибки записи
и сигналы. Исходники тестов находятся в tests/.
Дополнительно проверяются две конфигурации с одновременными максимальными
значениями всех числовых параметров и ошибка записи stdout в /dev/full.

Дополнительные проверки потоков находятся в `tests/test_threads.c` и
`tests/test_threads.py`: выполнение ходов рабочими потоками, ошибки создания
ресурсов, завершение участников и сравнение с последовательной версией.

В отдельном терминальном тесте проверяются кадры после каждого перехода,
совпадение номера клетки с положением машины, границы клеток, полный
журнал без управляющих кодов, ширина экрана и восстановление курсора
при SIGINT и SIGTERM. Прерывание отменяет длинные паузы.

Покадровая проверка дополнительно восстанавливает состояние по полному
журналу и сравнивает с каждым кадром: клетки всех видимых машин, координаты,
событие, порядок, маршрут, стоимость, круги и финиши. Проверяются цвета команд
и выделение текущей машины. В четырёх сценариях сверены 4976 кадров
и 4010 переходов; журналы анимации, текстового режима и --quiet совпали.
Проверены оба порядка --no-animation и --delay при задержках 1 и 5000 мс.

Сборка с предупреждениями как ошибками и анализ GCC -fanalyzer прошли.
Проверки ASan/UBSan/TSan не выполнены: пробная компоновка подтвердила отсутствие
необходимых исполняющих библиотек в текущем окружении.
